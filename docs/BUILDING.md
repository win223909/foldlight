# Building from a clean checkout

Commands below run from the repository root. Build outputs and local configuration are ignored by Git.

## Web

Node.js 20+. No npm packages to install.

```sh
npm run dev
npm test
npm run build
```

Development URL: http://127.0.0.1:4178. `FOLDLIGHT_PORT=4196 npm run dev` changes the port. Serve `build/WebRelease/duo-static` on HTTPS for physical phone motion. Download buttons use versioned hosted files; they are not local build prerequisites.

## Android / Fold8

Install JDK 17, Android SDK Platform 35 and Build Tools 35.0.0 using Android Studio or `sdkmanager`. Set `ANDROID_HOME` to your SDK path, or create `android/local.properties` with your own `sdk.dir` (never commit it).

```sh
./android/gradlew -p android testDebugUnitTest lintDebug assembleDebug
python3 -m unittest discover -s android/tools -p 'test_*.py'
```

Output: `android/app/build/outputs/apk/debug/app-debug.apk`. The wrapper distribution checksum is pinned. A local debug signing key is generated by Android tooling; it will differ from the hosted beta's key. Use your own release signing process for production and preserve it for updates.

Real GPU / gesture tests require a compatible unlocked device:

```sh
./android/gradlew -p android connectedDebugAndroidTest
```

These tests may change temporary settings or concurrent display state; use a dedicated test device. Hardware validation is separate from JVM test/build success. See [android/README.md](../android/README.md) for Shizuku setup.

## iPhone

Install Xcode 26.5 or newer. Open `DuoLikeAnimation.xcodeproj`, select the shared **Foldlight** scheme and an iPhone Simulator. The current deployment target is iOS 26.5. The upstream project/target names are preserved.

```sh
xcodebuild -project DuoLikeAnimation.xcodeproj -scheme Foldlight \
  -configuration Debug -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath build/iOS CODE_SIGNING_ALLOWED=NO build
```

For physical installation, choose your own development team and unique bundle identifier in Signing & Capabilities. No team, certificate or provisioning profile is included. The sample identifier is `com.example.foldlight.ios`.

Run Xcode's Test action on a suitable simulator/device for photo storage and GPU tests; simulated orientation does not validate physical tilt. CI performs a simulator build without signing or device installation.

## Mac

Install full Xcode and select it with `xcode-select` if necessary. The script builds Apple Silicon and Intel code for macOS 13+, then signs ad-hoc by default.

```sh
./macos/build.sh
./scripts/test-macos.sh
```

Output: `build/MacApp/Foldlight.app`. The tests require Metal hardware and use generated images; CI performs a universal build because hosted runner GPU support varies. Set `FOLDLIGHT_SIGN_IDENTITY` only to an identity from your own keychain when you need signing. Notarization is a separate distribution step.

## Optional analytics

Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/pip install -r analytics/requirements.lock
.venv/bin/python -m unittest discover -s analytics/tests -v
```

Deployment requires your own Access identity, audience, allowed admin and log paths. See [analytics/README.md](../analytics/README.md). Never expose the test-only preview server or commit visitor data.

## Before a pull request

```sh
git add <your-files>
npm run check:public
```

Review staged changes as well as automated scan output. CI does not deploy or read production credentials.
